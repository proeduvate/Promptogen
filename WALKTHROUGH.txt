 1. HOW TO RUN
-------------------------------------------------------------------------------

 Open a terminal in the project folder and run:

     npm install        (only needed the first time)
     npm run dev        -> starts dev server at http://localhost:5173
     npm run build      -> production build into /dist
     npm run preview    -> serve the production build locally

 4. THEMING - HOW LIGHT / DARK WORKS
-------------------------------------------------------------------------------

 The entire palette lives as CSS custom properties in src/index.css:

     :root[data-theme="dark"]  { --c-bg: #080b13; --c-surface: #0c111d; ... }
     :root[data-theme="light"] { --c-bg: #f6f8fc; --c-surface: #ffffff; ... }

 Tailwind's @theme block maps utility names onto those variables, so
 classes like bg-surface, text-muted and border-line resolve at runtime.

 App.jsx writes the attribute:

     document.documentElement.dataset.theme = theme

 Flipping that one attribute re-skins the whole app. There are no
 duplicated "dark:" variants anywhere in the codebase, and no component
 has to rerender for the theme to change.

 The sun/moon control in the top bar is a real radio group and it works.
 Dark is the default, matching the mockup.

 5. PAGE LAYOUT
-------------------------------------------------------------------------------

 App.jsx holds four pieces of state:

     theme       "dark" | "light"
     activeNav   which sidebar item is highlighted
     idea        the hero textarea contents
     modalOpen   whether the wizard is showing

 The main area is a CSS grid of [ 1fr , 312px ] with four children in
 this order:

     Hero            StrengthPanel
     FeatureCards    WhyPanel

 That ordering is what makes the feature row and the "Why Promptogen?"
 card sit on the same row, exactly as in the mockup.

 Below the xl breakpoint the grid collapses to a single column and the
 sidebar is hidden.

 IMPORTANT: content is data, not markup. The nav items, example chips,
 feature cards, the five score metrics and the benefits list all live in
 src/data/content.js, each with its own icon and color token. Changing
 copy never means touching a component file.

 6. INTERACTION WALKTHROUGH
-------------------------------------------------------------------------------

 6.1  HERO COMPOSER

   - Type an idea into the textarea. The counter caps at 500 characters.
   - Press Enter, or click the blue "Enter" button, to open the wizard.
   - Shift+Enter inserts a newline instead of submitting.
   - The Enter button is disabled while the input is empty.
   - Clicking any of the 5 example chips (Marketing Campaign, Code
     Generator, Blog Writer, Product Description, Lesson Plan) drops a
     full seed sentence into the textarea - not just the chip label - so
     the next step has real text to work with.

 6.2  OPENING THE WIZARD

   Submitting opens QuestionsModal with seed={idea}. That seed pre-fills
   the step 1 "main goal" field, truncated to its 200-character limit.
   Every time the modal opens it resets to step 1 with fresh answers.

 6.3  HOW THE WIZARD IS BUILT (the important part)

   The modal is entirely data-driven. src/data/wizard.js defines all four
   steps as configuration, and the renderer only knows three field types:

       textarea   bordered box with an inline character counter
       cards      icon tiles with a checkbox (multiple: true)
                  or a radio dot (multiple: false)
       select     styled native dropdown with a chevron

   Adding, removing or reordering a question is a config edit, not a
   component edit. You never have to write JSX to change the questions.

   Step 1 (Goal) fields, matching the mockup:
       goal          textarea, required, 200 char limit
       outputTypes   cards, multi-select, required
                     (Analysis/Insight, Step-by-step Guide, Creative
                      Content, Code/Technical, Other)
       audience      select, required

   Steps 2-4 use the same three primitives:
       Context        background, domain, priorAttempts
       Requirements   mustInclude, length, format
       Preferences    tone, model, notes

 6.4  NAVIGATION RULES

   - "Next" stays disabled until every required field on the current
     step has a value.
   - On step 1 the left button reads "Cancel". From step 2 onward it
     becomes "Back" with a left arrow.
   - Completed step circles turn into blue checkmarks and can be clicked
     to jump backwards. Future steps are not clickable.
   - On step 4 the right button reads "Generate Prompt" instead of
     "Next", and calls onComplete(answers).
   - Moving to a new step scrolls the modal body back to the top.

 6.5  DISMISSING THE MODAL

   Any of these close it: the Escape key, the X button, the Cancel
   button, or clicking the dark backdrop.

   While the modal is open, background page scrolling is locked. The
   previous scroll setting is restored on close.

 7. WHERE TO PLUG IN REAL LOGIC
-------------------------------------------------------------------------------

 handleComplete in src/App.jsx is the single hand-off point. Right now it
 just console.logs the collected answers:

     const handleComplete = (answers) => {
       console.log("Wizard answers", answers);
       setModalOpen(false);
     };

 The answers object is flat and keyed by field name, so it serializes
 straight into a request body:

     {
       goal:          "...",
       outputTypes:   ["analysis", "guide"],
       audience:      "Developers",
       background:    "...",
       domain:        "...",
       priorAttempts: "...",
       mustInclude:   "...",
       length:        "...",
       format:        "sections",
       tone:          "professional",
       model:         "Claude",
       notes:         "..."
     }

 After handleComplete the Home area switches to the Generated Prompt
 screen, which currently shows the sample prompt from data/generated.js
 (the answers are not yet used to build it).

 Other stubs waiting for real behaviour (console.log hand-offs):

     - Generated prompt: Regenerate, Improve Prompt, Convert to

-------------------------------------------------------------------------------
 8. NOTES AND KNOWN GAPS
-------------------------------------------------------------------------------

 - The score data (85/100, Clarity 90, Specificity 85, Context 80,
   Structure 85, Actionability 90) is hardcoded in src/data/content.js.
   Metric bars render green at 85 and above, amber below - that rule is
   the barTone function in StrengthPanel.jsx.

 - Icons are a best-guess match to the small glyphs in the mockups.
   "Smart Questions" uses Compass and "My Prompts" uses LineChart. If
   either looks wrong, each is a one-line import swap in
   src/data/content.js.

 - The starfield dots in the hero use fixed coordinates so they do not
   jump around on rerender. The paper plane and its dashed trail are
   inline SVG, hidden below the xl breakpoint.

 - This build was verified by compiling (npm run build passes clean,
   1583 modules, no errors) but was NOT visually diffed against the
   mockups in a browser, because the browser automation extension was
   not connected during the build session. Please eyeball it at
   http://localhost:5173 and report anything that looks off.
